# Windows 双板一键通信测试

三块 ESP32 已按 `docs/K7_开发架构方案.md` 第 8 节烧录，两个从车的 LEADER_MAC 已填实际主车地址后使用。这个工具在 Windows 电脑运行，测试链路为：电脑 → 主车 USB → ESP-NOW → 从车 USB → 电脑。

## 使用

1. 电脑安装 Python 3.9+（包含 pip）。Git Bash 用于 `.sh` 入口；也可直接双击 `.cmd`，无需 Bash。
2. 用两根数据线同时连接主车和 car2，关闭 Arduino 串口监视器。
3. 双击 `run.cmd`；或在 Git Bash 执行 `bash run.sh`。
4. 等待约 73 秒：发送 60 秒、停止发送 3 秒、恢复发送 10 秒。
5. 脚本释放串口后提示换车。保留主车，换上 car3，按回车再次自动识别测试。

首次运行自动检查 pyserial；缺少时下载 pyserial 3.5 到本目录 `.runtime/`，需要网络。CH340 驱动应已在烧录时配置好。

自动识别范围是沁恒 USB VID 1a86 的串口，按固件 StatusPacket 判定主车和从车；测试时只接本次两块开发板。其他 USB 转串口型号可显式指定端口：

```bash
bash run.sh --ports COM3 COM7
```

一次测试后直接退出（退出码 0=通过，1=失败，130=中断）：

```bash
bash run.sh --once
```

`.cmd` 同样接受这些参数。串口号无需写入源码，换车后自动重新枚举。

## 检查内容

- 读取两块固件上报的实际编号、角色、信道、STA MAC。
- 给主车注入新时间戳、递增序号的模拟 FleetState，复用原固件 96 字节协议。
- 将从车回传内容逐帧与电脑实际发送内容比较，统计重复、乱序、缺失、延迟及间隔。
- 停止注入后留出 1 秒在途排空时间，随后检查缓存状态是否持续重播；再验证恢复收发。
- 每轮将 `result.json` 和完整收发十六进制 `frames.jsonl` 写入 `results/日期-编号/`。

通过门限：发送和恢复阶段分别至少收到 10、5 帧，整体接收比例至少 80%，同一发送阶段内相邻接收间隔最多 500 ms，内容错误/重复/乱序/其他测试来源/排空后的缓存重播/解析错误为零。门限用于室内台架排查，报告保留实际比例和间隔。该比例包含 ESP32 最新值合并、串口及无线的共同影响。

脚本展示测试状态和统计，不修改固件、主车 MAC、操作系统时间或 ROS 配置。它使用模拟状态，K7 的真实车辆信息仍由 `espnow_bridge` 接入。双板真实无线与 Windows 串口驱动行为需要在 Windows 连接开发板验收；本机可测试协议和 Linux 虚拟串口行为。

## 打包来源

仓库内直接导入 `ROS2_src/K7_ros2/src/k7_tasks/k7_tasks/espnow_protocol.py`。下载包中的同名协议副本由该源文件生成，更新后重新运行 `build_bundle.py`：

```bash
python3 build_bundle.py
```

生成 `k7-espnow-windows-test.zip`（忽略提交）。
