# K7 首次部署与验收

本指南面向现有 K7 / STM32 双轮差速硬件。架构与接口见 [架构手册](K7_开发架构方案.md)，日常命令见 [命令速查](ROS2_命令速查.md)。当前代码已在工作区，ROS/Keil 构建和实车验收尚未执行。

## 1. 硬件与系统

- K7：Ubuntu 24.04 ARM64、ROS 2 Jazzy。新板镜像和烧录工具按对应板卡版本确认；本地板卡资料在 `rk3576_data/`、`K7/`。刷写 eMMC 会覆盖原数据，先备份。
- K7 调试串口与底盘通信串口是两回事，不混用接线或波特率。底盘通过 CH9102F 连接 STM32 USART3，115200 / 8N1；K7 与底盘独立供电。
- 每车一套本地 USB 双目，左右并排输入；先核对 USB 带宽、左右顺序、固定安装与完整视野。
- STM32 只用 `Diff_Car` 目标；旧 GY53、STM32 APF/Stanley 和调试帧源码及 Keil 引用已删除。厂家共享硬件驱动与保护仍保留。
- 实车测试前确认可靠的现场停机方式。初次刷写后先架空轮子验证方向、速度与断链停车，再落地低速测试。

## 2. K7 软件部署

把仓库的 `ROS2_src/K7_ros2/` 部署为板端 `~/Code/K7_ros2/`，不要复制 PC 的 build/install。以下命令在 K7 Bash 执行：

已有旧版本时先停车退出 ROS，并备份板端自改源码、车辆参数和双目标定。在全新终端中，将板端旧 `src/` 重命名备份到工作区外，再完整复制本仓库 `src/`；不要用目录合并覆盖，否则已删除的旧包仍会残留。同步本工作区 README 和 setup_env.sh。确认当前目录为 `~/Code/K7_ros2` 后，清除可重建产物：

```bash
cd ~/Code/K7_ros2
pwd
rm -rf -- build install log
```

这会删除历史构建日志，需保留的先备份；不涉及仓库根目录的实验 `logs/`。旧源码备份不要放回本工作区。然后执行：

```bash
cd ~/Code/K7_ros2
bash setup_env.sh
source /opt/ros/jazzy/setup.bash
colcon list
colcon build --symlink-install --parallel-workers 2
source install/setup.bash
```

`setup_env.sh` 会安装系统依赖并修改 shell 的 ROS 环境入口，执行前阅读脚本；需要可用软件源。旧 overlay 不与当前构建混用。资源不足先降低并行度，不在故障未明时关闭安全节点。

串口和相机别名规则在 `src/k7_bringup/udev/`。先检查规则与本车 VID/PID/序列号是否匹配，再安装，不把多设备规则直接套用。核对：

```bash
ls -l /dev/k7_controller /dev/k7_camera
v4l2-ctl --list-devices
v4l2-ctl --device=/dev/k7_camera --list-formats-ext
groups
```

运行用户需要对应串口/视频设备访问权限；不要以长期 root 运行 ROS 代替权限配置。

## 3. 配置与双目标定

统一入口为 `src/k7_bringup/config/robot.yaml`。这是 launch 读取的分节点配置，不是可直接传给任意 ROS 节点的标准 `ros__parameters` 文件。每车复制到自己的绝对路径，用 `config:=...` 选择。

| 项目 | 必须确认的内容 |
|---|---|
| common | 实测轮距、首次低速上限、距离阈值、感知超时 |
| serial_bridge / usb_cam | 设备路径、波特率、相机分辨率/格式与支持帧率 |
| stereo_obstacles | 左右标定路径、原始单目尺寸、基线、安装高度/位置/俯仰/偏航、有效 ROI |
| controller_node | Stanley 控制点与增益、APF 距离、求解预算；先采用保守速度 |
| task_manager | 任务时间上限；编队时额外确认共同坐标变换 |
| experiment_recorder | 输出绝对路径、变量、选定话题、采样率和空间保护 |

标定默认使用 `src/k7_camera/config/left.yaml`、`right.yaml`；这些文件不能代替本车标定验收。需确认标定分辨率与输入左右半幅一致，左右投影矩阵包含有效基线。更换相机、焦距、安装姿态后重新确认。

`src/k7_camera/scripts/capture_calibration.py` 用于停机时采集标定图片，自带浏览器预览；`stereo_match.py` 用于离线核对校正/匹配，命令见[速查](ROS2_命令速查.md)。它们不是运行节点，不与 `usb_cam` 同时打开相机；标定求解仍须使用合适的双目标定工具，没有自动标定流程。

正常模式先保持 `calibration_confirmed: false` 启动，仅检查输入。完成标定和外参核对后再设 true，停车并重启。用已知距离障碍物检查距离、左右方向及遮挡；低纹理、逆光、黑色/透明物体和失配必须测试。未知深度应阻止运动，不能改为“无限远”来消除报警。调试深度图可临时设置 `publish_depth: true`，平时关闭。无感知功能测试可用 `test_mode:=no_perception`，此时不启动相机且没有避障，限速 0.05 m/s，只能在封闭空旷区域使用并安排现场急停。

## 4. STM32 部署

1. 打开 `STM32F407VET6_src/USER/WHEELTEC.uvprojx`，选择 `Diff_Car`，保留所需厂家库。
2. 核对 `USER/k7_config.h`：ROS-only、USART3、命令约 300 ms 超时、基础反馈 20 Hz、轮速和角速度上限。
3. 编译并保存完整警告/错误；本机尚未用 Keil 编译，不把本地 Python 测试当固件构建证明。
4. 架空刷写后检查开机不动、正向一致、零速停车。测试 ROS 进程退出、USB 拔除、无效帧与命令中断；用独立现场停机保护。
5. 落地测试前验证低压/禁能保护。软件时限不等于实测制动距离，制动距离应据此调整感知阈值和速度。

## 5. 分层验收

| 顺序 | 检查 | 通过标准 |
|---|---|---|
| 构建 | K7 全量构建、Keil Diff_Car | 无错误，保存版本和构建记录 |
| 静态链路 | 启动 trajectory，不下发任务 | IDLE、零速、odom/scan 新鲜；只有 guard 发布 cmd_vel |
| 拒绝运动 | 遮挡相机/标定未确认/底盘禁能 | 不授权，不把未知当可通行 |
| 断链 | 感知停更、任务/控制/串口退出 | 撤销权限、零速/固件超时停车；恢复不自动续驶 |
| 单车 | 低速直线与偏离后回线 | 前进和差速同时生效；横向/航向误差可记录 |
| 避障 | 已知静态障碍、狭窄或无可行路径 | 有空间时绕行，无空间时停车；不要求 APF 必然脱困 |
| 多车 | 共同坐标、起始队列、失联 | 每车本地感知，前车失联停车；见编队说明 |
| 负载 | CPU、延迟、USB/串口/网络、记录开启 | 实测满足周期，记录不挤占控制预算 |

无 ROS 依赖检查在仓库根目录执行 `python -m unittest discover -s tests -v`。它只覆盖纯逻辑/静态契约，不替代 DDS、驱动、定时、编译和实车验证。
