# K7 架构与接口手册

2026-10-25，描述当前工作区；K7 全量构建及无感知架空链路验证通过，固件和落地验收待执行。入口见 [文档目录](README.md)和 [CLAUDE](../CLAUDE.md)，可视化见 [架构图](k7-architecture.html)。本手册频率是默认配置/代码周期，不是完整性能基准。

图展示主数据流，不穷举手动转发、授权服务、状态回传和记录器订阅连线；完整接口以本文表格为准。
未完成模块的工作边界、依赖和验收证据见 [开发任务清单](开发任务清单.md)；本手册的接口约束仍以当前源码为准。

## 1. 职责与包

自有活动包共 7 个，不为每种算法复制任务、串口或记录器；外部 `usb_cam` 负责采集。

| 包 | 节点/资源 | 职责与启动条件 |
|---|---|---|
| k7_msgs | 无节点 | 3 个 msg、1 个 srv、2 个 action |
| k7_bringup | serial_bridge | 11/24 字节串口桥、odom 积分、底盘状态；另含统一 launch/config/udev |
| k7_camera | stereo_obstacles | 校正、SGBM、障碍扇区；不默认发布深度图/点云 |
| k7_control | command_guard | 授权、时效、传感器、底盘禁能、前进差速限幅；唯一最终速度出口 |
| k7_control | controller_node | APF + Stanley；仅 trajectory/formation 启动 |
| k7_tasks | task_manager | Action 生命周期、互斥、停车确认、遥控、编队参考轨迹 |
| k7_experiment | experiment_recorder | 常驻轻量节点；默认不写盘，可用 record 参数或记录服务启停 CSV、rosbag 和配置快照 |
| k7_description | URDF 等，无默认节点 | 保留模型能力，当前控制不依赖 robot_state_publisher/EKF |
| usb_cam（外部） | usb_cam | USB MJPEG 采集与解码；每车本地运行 |

源码都在 `ROS2_src/K7_ros2/src/`，仅保留以上 7 个自有包。旧算法包、串口实现、双目 splitter/depth 节点、旧 launch/运行脚本及兼容消息已删除。双目保留采集标定图片与离线匹配工具；运行时深度调试复用 `stereo_obstacles.publish_depth`。历史实现查 Git，不在活动源码树保存副本。

## 2. 话题

表中均为相对名称。namespace=car1 时，`odom` 实际为 `/car1/odom`；frame 为 `car1/odom` 和 `car1/base_link`，没有前导斜杠。编队输入是 goal 指定的绝对话题。

| 话题 | 类型 | 发布 -> 订阅 | 默认频率/条件 |
|---|---|---|---|
| camera/image_raw | sensor_msgs/Image | usb_cam -> stereo_obstacles | 10 Hz，3840×1080 并排 RGB |
| camera/camera_info | sensor_msgs/CameraInfo | usb_cam -> 调试客户端 | 驱动输出；不是双目左右标定来源 |
| perception/scan | sensor_msgs/LaserScan | stereo_obstacles -> controller_node、command_guard | 不超过 10 Hz，21 扇区 |
| camera/depth/image_raw | sensor_msgs/Image | stereo_obstacles -> 调试客户端 | publish_depth=true 且有订阅者时 |
| odom | nav_msgs/Odometry | serial_bridge -> task_manager、controller_node、command_guard | 随 20 Hz 上行帧 |
| imu/data_raw | sensor_msgs/Imu | serial_bridge -> 可选消费者 | 20 Hz，原始量；无姿态融合 |
| battery/voltage | std_msgs/Float32 | serial_bridge -> 可选消费者 | 不超过 1 Hz |
| chassis/disabled | std_msgs/Bool | serial_bridge -> command_guard | 20 Hz |
| tf | tf2_msgs/TFMessage | serial_bridge -> 可选消费者 | 20 Hz，odom -> base_link，可关闭 |
| teleop/cmd_vel | geometry_msgs/TwistStamped | 遥控客户端 -> task_manager | manual 才订阅，建议 20 Hz |
| control/reference | k7_msgs/ControlReference | task_manager -> controller_node | 路径任务 5 Hz；编队不超过 10 Hz |
| control/candidate | k7_msgs/MotionCommand | controller_node 或 manual task_manager -> command_guard | 自动 20 Hz；手动随输入 |
| cmd_vel | geometry_msgs/TwistStamped | command_guard -> serial_bridge | 30 Hz，空闲也发送零速 |
| control/status | diagnostic_msgs/DiagnosticArray | command_guard -> task_manager、controller_node | 1 Hz + 状态变化/服务请求 |
| task/status | diagnostic_msgs/DiagnosticArray | task_manager -> command_guard | 1 Hz + 状态变化 |
| fleet/state | k7_msgs/FleetState | task_manager -> 后车 task_manager | 不超过 10 Hz；publish_fleet=true 且对齐确认 |
| control/debug | diagnostic_msgs/DiagnosticArray | controller_node -> 可选 recorder | debug=true，不超过 5 Hz，字段可选 |

感知和 IMU 使用 sensor-data QoS；控制、参考、状态使用深度 1 的默认可靠 QoS。相机订阅使用 sensor-data QoS。过期数据不用于控制。`scan` 是双目推算的前向扇区，不是物理激光雷达；NaN 表示未知并禁止运动，有限有效样本支持的远处空间才可记为 inf。

## 3. 服务与 Action

| 接口 | 类型 | 所属节点 | 语义 |
|---|---|---|---|
| control/select_source | k7_msgs/srv/SelectSource | command_guard | 内部授权：NONE=0/MANUAL=1/AUTO=2；返回 success、permission_id、reason |
| control/hold | std_srvs/srv/SetBool | command_guard | true 锁定停车并撤销权限；false 解除锁定但不恢复旧任务 |
| task/set_manual | std_srvs/srv/SetBool | task_manager | manual profile 的开/关；true 等待授权结果 |
| task/stop | std_srvs/srv/Trigger | task_manager | 请求停车；响应仅表示受理，查看 task/status 确认停止 |
| experiment/record | std_srvs/srv/SetBool | experiment_recorder | 开始/结束一次实验；launch 参数 `record` 控制是否启动后立即记录 |
| task/follow_path | k7_msgs/action/FollowPath | task_manager | trajectory 专用，goal 含 Path、target_speed、position_tolerance、yaw_tolerance |
| task/follow_leader | k7_msgs/action/FollowLeader | task_manager | formation 专用，goal 含 leader_topic、gap、max_speed |

FollowPath 反馈：progress、lateral_error、heading_error、speed、state；FollowLeader 反馈：gap_error、lateral_error、leader_age、state。反馈不超过 2 Hz。两者 result：code（OK=0/CANCELED=1/FAULT=2）、reason；支持标准 ROS Action 取消。服务 stop 中止未取消的 Action，不伪报成功。

任务先申请权限，再输出带本次 UUID 的命令；停止先撤销权限，再等待新鲜里程计连续静止至少 0.3 s，3 s 未确认则 FAULT。一个任务结束前不能并行开始另一个。`task/stop` 可在故障排除后重新执行停车确认，回到 IDLE。hold 不是认证机制，也不是硬件急停：ROS 网络上的节点仍须可信，不能暴露给不可信网络。

## 4. 自定义消息

| 定义 | 字段与目的 |
|---|---|
| MotionCommand.msg | Header、permission_id(UUID)、Twist；阻止上一任务的迟到速度继续控制 |
| ControlReference.msg | Header、permission_id(UUID)、nav_msgs/Path、speed_limit；当前任务的有时效参考 |
| FleetState.msg | Header、session_id(UUID)、float64 x/y/yaw、float32 linear_speed/angular_speed、uint8 state；IDLE/RUNNING/STOPPING/FAULT |
| SelectSource.srv | source -> success、permission_id、reason |

定义目录：`ROS2_src/K7_ros2/src/k7_msgs/{msg,srv,action}/`，只生成表中当前接口。车间不传图片、深度图、完整 odom 协方差或整条路线。

## 5. 任务与扩展

统一用 ROS launch 管理节点和参数，不叠加另一套 shell 状态机。`setup_env.sh` 只安装环境；常用启动命令见 [命令速查](ROS2_命令速查.md)。

| profile | 常驻链路 | 如何开始 |
|---|---|---|
| manual | 相机、感知、guard、serial、tasks、空闲记录器 | 先持续发送零速 TwistStamped，再 task/set_manual=true；授权后持续更新遥控 |
| trajectory | manual 的基础节点 + 一个 controller | FollowPath goal；launch 不硬编码行驶任务 |
| formation | 同 trajectory；按需订阅前车状态 | FollowLeader goal，每车仍用本地双目 |

同一 profile 可顺序发送多个任务；换 profile/算法先停车并确认，再退出 launch、修改配置、重新启动。正常模式算法只接受 `apf_stanley`；传入 mpc 会明确失败，不静默回退。可选 `test_mode:=no_perception` 仅用于 trajectory/formation：不启动相机与双目，控制器仅运行 Stanley，guard 绕过 scan 就绪检查并将最终线速度限制为配置的 `test_speed_limit`（默认 0.05 m/s）。该模式没有避障或近障保护，须在封闭空旷场地使用并安排现场急停。手动模式不支持该测试模式。

后续接入新算法：实现同一 `ControlReference + odom + scan -> MotionCommand` 边界，复用权限、超时与记录；更新算法选择、参数与测试，仍然只启动一种。MPC 接入时须适配双目输入、限定求解预算和失效输出，再开放选择。规划器可通过 FollowPath Action 提交路径；当前不提供运行中轨迹热替换。GUI 用现有任务/停车/记录接口，不直接控制串口或 cmd_vel。避免为尚未实现的算法预建空包。

## 6. 控制与 STM32

Stanley 使用前方控制点、路径切线航向误差及 `atan2(k*cte, |v_measured| + soft_speed)` 得到等效转向角，再以 `w = v*tan(delta)/control_point` 转为差速车角速度。APF 按障碍降速并叠加转向，最后联合限幅：`v_left=v-w*track/2`、`v_right=v+w*track/2`。限制两轮非负、按比例缩放到最大轮速；行进和转向同时输出。前方控制点可提前修正航向，但不保证有延迟/扰动时横向误差为零就一定航向误差为零。路径终点依据末段位置投影判断，沿 +x 的直线等价于 x 过终点；航向不满足容差时故障停车，不越过终点反复追踪。

固件位置：`STM32F407VET6_src/USER/k7_config.h`、`BALANCE/balance_task.c`、`BALANCE/uartx_callback.c`、`BALANCE/data_task.c`。

- 仅 USART3 合法 11B 帧可更新 ROS 命令；mode/reserved/Vy 必须为零，BCC/帧尾匹配且速度在上限内。
- 100 Hz Balance_task 消费命令、差速联合限幅和轮速 PID；约 300 ms 无合法新命令强制禁能。空闲零速帧维持通信，不等于授权运动。
- 禁用启动自动试车、旧遥控/回充运动覆盖；原低压和急停/禁能检查仍保留，需实车验收。
- 20 Hz 仅发 24B 基础反馈；不发 0xFA/0xFB 红外或算法调试帧，不向其他串口/CAN复制遥测。
- 固定速度上限 0.35 m/s、角速度上限 1.2 rad/s；硬件参数和轮速 PID 仍沿用已有固件，不在 ROS 重写。

## 7. 计算与通信预算

| 链路/任务 | 默认预算 | 注意 |
|---|---|---|
| 串口下行 | 11B × (1000/33) Hz，约 333B/s | 8N1 占线约 3333bit/s，115200 的 2.9% |
| 串口上行 | 24B × 20Hz = 480B/s | 约 4800bit/s，4.2%；全双工分方向计算 |
| 双目 SGBM | 每眼 480×270、64 视差、10Hz、OpenCV 2 线程 | 主算力负担；保留原分辨率采集是为匹配现有标定 |
| 原始 RGB topic | 3840×1080×3×10，约 124MB/s | 本地逻辑数据量，不是 USB MJPEG 码率；避免远端订阅 |
| 控制 | 20Hz，路径最多 512 点 + 21 扇区 | O(N+S)，无优化器；默认单次预算 40ms，超预算不发新候选 |
| 编队 | 10Hz、历史最多 256 点、3cm 间隔 | 单车只订阅前车；FleetState 几何+速度+状态为 33B，另有 Header/UUID/CDR/DDS 开销 |
| 参考路径 | 单车 5Hz、编队至多 10Hz，仅车内 | 最大 512 PoseStamped；并非零拷贝，按实测再优化 |
| 记录 | CSV 5Hz，默认关闭；bag 按选定话题原频率 | 30min/512MB 磁盘余量保护，图像默认不录 |

serial_bridge 以 5ms 周期检查接收，并不以 200Hz 发送遥测。command_guard/candidate/串口分别有独立时效检查；固件最终超时不依赖 ROS 正常退出。

namespace 只分名字，不隔离 DDS 网络。默认未订阅的远端图像没有用户数据接收者，但 DDS 发现仍存在；不要在调试机运行全量录包或订阅所有图像。严格跨机隔离需进一步配置 DDS 分区/路由白名单并实测，当前未实现。没有测量前不承诺具体 CPU 占用或端到端停车距离。
