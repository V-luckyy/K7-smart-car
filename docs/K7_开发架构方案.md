# K7 智能小车 — ROS2 (Jazzy) 开发架构方案（终稿）

> 2026-07-20 定稿。项目文档参照 `CLAUDE.md`，硬件事实以 CLAUDE.md 第 13 节为准。

## 一、已确认的决策

| 决策项 | 结论 |
|--------|------|
| ROS2 版本 | **Jazzy**（匹配 K7 官方 Ubuntu 24.04；wheeltec 参考代码是 Humble，移植注意 API 差异） |
| 代码位置 | `ROS2_src/K7_ros2/`（colcon 工作区），wheeltec 留在 `ROS2_src/wheeltec_ros2/` 只读参考 |
| 主控↔底盘通信 | **USB 转串口**：K7 USB Host → CH9102F → STM32F407 USART3，`/dev/k7_controller`（udev 别名），115200 8N1，无需电平转换 |
| 手柄 | 2.4G 无线接收器插 K7 USB，内核枚举为 `/dev/input/js0`，与有线无区别，标准 `joy` + `teleop_twist_joy` |
| 摄像头 | LRCP 2MV USB 双目（单设备输出 3840×1080 左右并排帧），V4L2 采集，双目基线 ~20mm |
| 开发工作流 | 在 Windows 仓库写码 → `scp -r ROS2_src/K7_ros2/ kickpi@<K7_IP>:~/code/` → K7 上 `colcon build`；VSCode Remote-SSH 用于板上编译调试 |

## 二、硬件事实摘要（CLAUDE.md 13 节，固件源码已核实）

- 底盘：WHEELTEC C50X，C50C 主控 V1.0，**STM32F407VET6**，两轮差速
- 轮距 0.329m / 轮径 0.125m；500 线编码器 ×4 倍频；减速比 27/51 由电位器档位定（固件内部换算，ROS 端无需关心）
- 协议与 wheeltec **逐字节一致**：下行 11B / 上行 24B，int16 大端 ×1000，BCC 含帧头，上行 20Hz
- 上行速度是**整车速度**（固件已做正运动学），IMU 是 MPU6050 原始值（±2g/±500dps），系数与 wheeltec ROS 端匹配
- ⚠️ **固件断链不停车**（SecurityLevel 默认关闭）→ K7 侧 ROS 层必须实现 cmd_vel 看门狗
- 自动回充：固件完整支持（0x7C 帧 + 红外对接），本期不启用
- 红外测距×3：固件未采集，数据不上行，当前不可用
- 供电：双电池独立，K7 插电自启，两板经 USB 线共地

## 四、工作区结构

```
K7_ros2/                      ← colcon 工作区（build/ install/ log/ 已 gitignore）
└── src/
    ├── k7_bringup/     # C++ 串口节点（移植+看门狗）+ 核心 launch + ekf/imu 配置 + udev
    ├── k7_description/ # URDF（差速双轮+万向轮+相机 frame）+ robot_state_publisher
    ├── k7_camera/      # Python 双目 splitter + 标定 yaml + launch
    ├── k7_nav/         # 【Phase 4 再建】nav2 参数 + twist_mux/depthimage_to_laserscan 配置 + 地图
    └── k7_npu/         # 【Phase 5 再建】rknn 检测节点（订阅左目图）
```

自研节点只有 3 个：串口节点（移植）、splitter（定制硬件适配）、NPU 检测（Phase 5）。

## 五、节点 / 话题 / TF

```
/joy ──→ teleop_twist_joy ──────→ /cmd_vel_joy ─┐
teleop_twist_keyboard ──────────→ /cmd_vel_key ─┼─→ twist_mux ──→ /cmd_vel ──→ k7_serial_node
(Phase4) Nav2 ──────────────────→ /cmd_vel_nav ─┘  优先级 joy>key>nav        │ 看门狗 500ms
                                                                              ↓ /dev/k7_controller
k7_serial_node ──→ /odom, /imu/data_raw, /PowerVoltage
/odom + /imu/data_raw ──→ ekf_node ──→ /odom_combined (+TF odom_combined→base_footprint)
/imu/data_raw ──→ madgwick ──→ /imu/data

usb_cam(/dev/k7_camera) ──→ /camera/image_raw(3840×1080)
    ──→ splitter ──→ /camera/left|right/image_raw + camera_info
    ──→ stereo_image_proc ──→ /camera/disparity, /camera/points   (需先标定)
```

- TF：`map(Phase4) → odom_combined → base_footprint → base_link → 轮/万向轮；base_footprint → gyro_link、camera_link → camera_left/right_optical_frame`
- **沿用 wheeltec 命名**（`odom_combined`、`base_footprint`、`gyro_link`、`/imu/data_raw`、`/PowerVoltage`）：EKF/Madgwick/Nav2 的 wheeltec 参数按这套命名调好，零改动复用
- cmd_vel 仲裁：`twist_mux`，优先级 **joy > keyboard > nav**（手柄永远能抢回控制权）
- 看门狗只放串口节点：指令链最后一道闸，上游任何节点崩溃都兜底

## 七、风险与注意

1. **看门狗是第一优先级安全需求**，Phase 2 验收必须包含断链停车测试
2. wheeltec 是 Humble 代码，Jazzy 移植已知坑：launch 语法基本兼容；`robot_localization`/`imu_filter_madgwick` 参数格式微调；colcon 编译警告升级
3. 双目基线仅 ~20mm，有效测距范围有限（预计 0.3~1.5m 可用），Phase 4 避障按近距设计
4. 串口节点依赖 wjwwood serial 库：优先 `rosdep` 安装；若无 Jazzy 包则把 3 个源文件 vendor 进 k7_bringup
5. K7 三个 USB3 口分配：摄像头（独占带宽）、CH9102F、手柄接收器，不要经无源 Hub 并联摄像头
