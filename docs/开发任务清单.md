# K7 后续开发任务清单

本清单是**待做工作**，不是功能完成声明。当前事实见 [CLAUDE.md](../CLAUDE.md)，节点/消息/频率见 [架构手册](K7_开发架构方案.md)，操作与测试顺序见 [上手指南](K7_上手操作指南.md)。2026-10-25 仅完成板端 ROS 7 包构建与单车**架空、无感知**链路验证；编码器积分的 odom 不代表真实车身轨迹。以下任务按依赖交付，不要同时启动替代控制器或恢复历史包。

## 交接规则

领取一个编号任务，在独立分支/PR 完成。将该行的目标、文件边界、验收条件连同本页链接交给负责人的 agent；先读根目录 `CLAUDE.md` 和相关源码/测试，再动手。输出必须区分：源码变更、本机测试、K7 编译、STM32 编译/刷写、架空测试、落地测试；没做的明确写未验证。参数改 `src/k7_bringup/config/robot.yaml`（固件安全上限改 `USER/k7_config.h`），记录实验用 `record`/记录服务和 `logs/README.md`，生成数据不提交。接口变动需同步架构手册、启动命令、回归测试及 `CLAUDE.md` 对应事实；不能改源码接口而留下文档里的旧合同。保留无关的用户修改。

| 顺序 | 任务 | 负责边界与预期交付 | 验收证据 / 前置条件 |
|---|---|---|---|
| A | 固件版本与独立停车 | `STM32F407VET6_src/USER/k7_config.h`、`BALANCE/{balance_task,uartx_callback,data_task}.c`；核对现烧固件与仓库目标，编译 `Diff_Car`，仅在发现问题时改固件/串口协议。不要把规划/避障搬回 MCU。 | Keil 构建记录、版本/刷写记录；先架空测开机零速、正常速度、命令中断、USB 断链、无效帧、禁能与低压；记录停止时间与独立现场停机方法。**固件身份未核实前不做落地测试。** |
| B | 可行参考路径与连续进度 | `k7_tasks/k7_tasks/{ref_path,task_manager}.py`、`k7_control/k7_control/core.py`，对应 `tests/`。明确用户要求的原点起步、两圈外径 3 m 螺线，与前进且车轮不反转的转弯约束冲突：中心起点约 0.06 m 曲率半径，现控制器下限约 0.24 m。先提交可行性结论/备选路径方案供确认，**不得悄悄改变指定螺线或宣称已走完两圈**。 | 单元测试覆盖邻近圈段投影、进度单调性、终点判定及不可达曲率；用现有架空 bag 作回归，检查能否拒绝“跳圈后到终点”假成功。落地轨迹验收要等 A 和场地准备。 |
| C | 双目有效测距 | `k7_camera/config/`、`k7_camera/k7_camera/{stereo_obstacles,stereo_geometry}.py`、本车 `robot.yaml` 与相关测试。每车完成实际左右标定、安装外参、分辨率/左右顺序和视野检查；必要时修正深度到 21 扇区算法。未知值保持不可通行，不增加常态深度/图像跨车话题。 | 标定文件与现场测量记录；用已知距离/左右方位、遮挡、低纹理、逆光等样例验证扇区和失效停车。未验收前保持 `calibration_confirmed: false`；不是修改参数为 true 就算完成。 |
| D | 单车落地循迹/避障 | A、B、C 均通过后，负责 `k7_control/k7_control/{core,controller_node,command_guard}.py` 和必要的参数/测试；任务与串口边界不另起第二套。先直线、大半径圆弧、回线，后静态障碍；采集横向/航向误差、双轮速度、停车状态。 | 现场急停和封闭场地；记录带/不带障碍的 CSV/bag，按任务类型分别证明前进与转向同时生效、避障后重新循迹、未知/过近停车。记录实测误差与制动距离，不能用架空积分结果代替。 |
| E | 编队逐级验证 | A、D 后用 `k7_tasks/k7_tasks/{task_manager,formation}.py`、`FleetState` 和每车配置；先无感知空场地双车，再扩到三车，最终每车恢复本地双目。共用 fleet 坐标需实测初始变换、同一时钟与独立 namespace；车间只传前车 `FleetState`，不传图像、scan 或全路径。 | 记录队距/横偏与车间带宽，验证前车失联/重启、后车自身障碍、任一车停车时的权限撤销与静止；逐车核对参数及日志。无感知测试限速且不具备避障，不能作为最终编队安全验收。 |
| F | 负载与记录基线 | 与 C/D/E 并行取各阶段数据，负责 `k7_experiment` 配置、`k7_bringup` 启动参数与测量报告；默认只录必要状态、控制及本地选定话题。 | 分别记录单车/三车、有无 `record` 的 CPU、内存、控制周期超时、串口丢帧、USB/网络带宽、磁盘余量；与架构手册中的**设计周期**比较。发现超预算时再定位优化，先确保停车与丢包行为不退化。 |

顺序：A 与 B/C 可并行；D 依赖 A+B+C；E 依赖 D；F 随各阶段采样并汇总。路径规划器、替代算法（包括 MPC）和 GUI 暂不占活动包：有明确实验需求时另开任务，沿用 `FollowPath` 或 `ControlReference + odom + scan -> MotionCommand` 接口、现有权限/停车/记录链路；一次只启用一个算法。新算法须补输入失效、计算超时和互斥验证，不能绕过 `command_guard`。不要为未来功能预建空包或占用带宽。

交付：最小源码和测试变更、配置/文档对应更新、复现实验命令与日志位置；逐项报告已测/未测及剩余风险。
遇到几何/安全约束冲突先提交证据和选项，不自行放宽安全限制。
